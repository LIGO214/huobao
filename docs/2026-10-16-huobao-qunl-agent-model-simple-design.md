# 火宝接入 Qunl Agent 模型简化设计

日期：2026-10-16

修订：2026-10-18。当前执行规则见第 0 节；第 1 至 10 节保留为历史设计，不再作为执行要求。真实部署和完整业务尚未验收。

本轮范围：保留原有用户模型配置和调用流程，补齐用户隔离；不增加 Token 绑定、双来源、自动任务恢复或删号联动。

- `docs/2026-10-16-huobao-qunl-multi-tenant-design.md`

## 0. 当前执行方案

### 0.1 保留原流程，只补用户隔离

Qunl 负责登录、账号状态和模型服务；火宝保留原有模型设置页，每个用户保存自己的 Key、Base URL、模型、协议、用途、优先级和启用状态。火宝不计费、不管理渠道，不建设自动选 Token、绑定表、能力目录或 `qunl/legacy_private` 双来源。

```text
浏览器 -> Qunl Session -> /huobao/* 代理 -> 签名用户 ID -> 火宝业务
火宝 -> 当前用户保存的 Key 与 Base URL -> Qunl 公开兼容接口 -> 上游
```

登录签名和模型 Key 是两条独立链路。用户归属只取代理认证后的上下文，不能取请求体或 Key。Qunl Session Cookie 不发给火宝；模型请求使用用户配置里的凭据，不使用代理签名。Key 有效性、模型权限和额度由 Qunl 公开接口检查，火宝不新增 Token 所有权查询或逐步账号状态查询。用户主动分享 Key 不属于火宝数据授权，系统不能自动提供其他用户保存的 Key。

### 0.2 接口与扩展点

| 用途 | 协议 | 路径 |
| --- | --- | --- |
| 文本 Agent | OpenAI 兼容 | `/v1/chat/completions` |
| 图片 | OpenAI 兼容 | `/v1/images/generations`、`/v1/images/edits` |
| 火山视频 | Volcengine v3 | `/api/v3/contents/generations/tasks` 及 `/:id` 查询 |

Base URL 由用户填写，协议前缀由已有 URL 函数集中拼接，不重复加 `/v1`、`/api/v3`，不默认加厂商目录，不按模型名猜旧接口。其他现有 Adapter 保留；新增协议只扩展集中协议规则与 Adapter，不在业务路由写用户分支。Qunl 启动不再注册旧 `/internal/huobao/*` 自动选 Token 模型入口，旧文件保留但业务不引用。

`dreamina-seedance-2-0-mini-260615` 是已有公网实测成功的低成本候选，不是所有用户写死的模型；通用 `/v1/models` 未列出它不能证明视频不可调用。

### 0.3 配置边界

继续使用带非空 `user_id` 的 `ai_service_configs`，不新增来源或选择表。列表、详情、创建、更新、删除、测试、运行均经过租户数据模块；跨用户统一 404。

- API 仅返回 `has_api_key`，不回显 Key；编辑表单 Key 为空，留空不提交，保留原值。新增必须提供 Key，显式空值拒绝。
- 用途与协议集中校验；更新在行锁内验证最终组合。被剧集引用的配置不能删除或改用途，可以停用。
- 显式选择失效、停用、跨用户或用途错误的配置时失败，不换默认 Key。未显式选择时沿用本人配置优先级及剧集锁定规则，无可用配置时报错。
- 选项用配置 ID 与模型名区分，同协议同模型但不同 Key 不合并。
- 连通性测试不返回上游正文，仅表示接口响应，不代表真实生成成功。
- 不新增独立加密轮换平台，但数据库、备份、配置按含密钥数据保护，不进入仓库、公共目录或日志。

只读核对已确认 Qunl 用户 1 为启用的 root，测试 Key 属于用户 87、Token 2054。root 旧配置只归 1，测试配置只归 87，不按首个访问者认领，不把素材令牌当旧模型 Key。该核对不等于迁移：root 原 Key 尚未逐项核对并真实迁入；迁移显式传所有者，运行逻辑不写死 1 或 87。

### 0.4 Agent 与任务

共享 Agent 代码和内置指令，每次运行独立传用户、项目、剧集、配置和请求 ID。Prompt/Skill 仅为本人纯文本补充，不上传脚本、定义工具或访问文件；工具由租户数据层授权。本次指令快照冻结，运行中修改只影响下次任务。完整模型配置尚未冻结：Agent 按配置 ID 在步骤中验证有效性，图片视频使用本次捕获的配置，不把完整模型快照作为本轮要求。

保留用户级/全局原子准入、存储、上传字节/像素/在途数限制及基本超时，不引入队列。正式媒体、字幕、缩略图、海报、合并与临时输出均受同一存储限制，超限不发布半文件。

本地失败、超时、重启中断结束本地工作并释放本地名额；已有上游 ID 保留，不自动重提付费请求。本地停止不等于上游停止，上游仍可能运行或计费，不展示为上游已取消。不增加上游取消、自动恢复、租约、失联核对平台或失效 Token 收尾通道；本地并发限制不承诺覆盖失败后仍在上游运行的任务。

### 0.5 账号、存储与验收

账号生命周期沿用 Qunl：禁用或删除后拒绝新的火宝访问，在途任务不逐步查询账号，不阻塞 Qunl 删号，不承诺本阶段同步清理火宝资产。

本地、测试和正式 Web 均用 PostgreSQL，SQLite 仅作迁移输入。旧数据离线按显式所有者迁移，复制校验、数据库导入、目录发布分阶段记录并可继续，原文件不自动删除。用户媒体在本人目录，授权先于 Range/HEAD，缓存为 `private, no-cache`，业务响应为 `private, no-store`。

图片参考图只允许本人站内图片；视频参考素材下一阶段接入和实测，本阶段入口关闭，不公开用户目录、不发送需 Cookie 的私有地址、不静默丢素材。

本轮验收配置 CRUD、实际 SDK/Service 按用户使用 Key、错误配置不回退、媒体和任务隔离、重启不重提、设置页编辑和移动布局。真实 Qunl Session、配置迁移、部署和完整双用户业务仍须另行验收；临时签名测试入口和历史公网成功记录不能代替。不开启真实多用户入口，不重复调用付费模型，不修改真实 Qunl 数据。

## 1. 历史目标

> 历史设计从本节开始，仅供追溯，不再作为执行要求；当前模型、任务与账号规则只取第 0 节。

本阶段只做三件事：

1. 火宝正式 Web 使用 PostgreSQL。
2. 火宝继续使用共享 Agent，但每次 Agent 运行都带当前用户上下文。
3. 新用户模型和 API 从 Qunl 接入，火宝不管理其 Key、渠道、额度或计费。旧 Key 按最新确认原值保留给指定用户，只能显式选择，不能共享或自动回退。

简化后的调用链：

```text
浏览器
  -> Qunl 登录
  -> Qunl /huobao/* 代理
  -> 火宝 Agent
  -> Qunl 模型 API
  -> 上游模型
```

火宝负责剧本、资产、分镜、Agent 工具和用户数据隔离。Qunl 负责账号、模型配置、API Key、渠道和计费。

### 1.1 现有接口核对结论

Qunl 当前已经提供火宝需要的主要兼容接口，首版不再新建一套模型网关：

| 能力 | Qunl 现有接口 | 火宝当前适配情况 | 首版规则 |
| --- | --- | --- | --- |
| 文本 | `/v1/chat/completions`、`/v1/completions` | Agent 已能按 OpenAI/Gemini 配置调用 | 统一通过 Qunl 模型来源调用 |
| 图片 | `/v1/images/generations`、`/v1/images/edits` | OpenAI 图片 Adapter 已匹配 | 文生图和参考图优先走 `/v1` 兼容接口 |
| 火山视频 | `/api/v3/contents/generations/tasks`、`/api/v3/contents/generations/tasks/:id` | 火山视频 Adapter 已匹配创建和轮询 | 直接复用 Qunl 火山兼容接口 |

这里要区分两件事：

1. **兼容协议已有**：Qunl 提供上述接口，火宝已有 Adapter；当前仍有按模型前缀选择旧视频路径的分支，不能把适配器存在说成完整流程已通。
2. **内部接入不等于验收完成**：当前已增加签名模型入口，但 PostgreSQL、明确 Token 绑定、旧配置私有迁移和真实双用户业务仍需落实；此前记录见执行计划第 16 节。

公开协议使用以下路径约束；正式 Qunl 来源通过内部前缀调用，完整路径见第 3.2 节：

- Qunl 根地址集中配置，客户端追加完整 `/internal/huobao/v1/*` 或 `/internal/huobao/api/v3/*`；
- 不重复拼接内部前缀；历史来源保留原 Base URL，按明确协议追加兼容路径；
- 不默认追加 `/volcengine`、`/qwen`、`/minimax` 等路径前缀；
- 只有外部网关明确提供这些前缀时，才允许作为独立适配器配置，不能把它们写成 Qunl 标准路径；
- 火山图片 `/api/v3/images/generations` 不作为 Qunl 标准接口，图片首版走 `/v1/images/generations`。

Qunl 现有公开兼容接口继续负责模型路由、额度和计费。正式 Web 首版固定使用一个很薄的内部模型转发入口，把已验证的 `user_id` 映射到现有 relay，不把长期 API Key 交给火宝。入口只允许文本、图片和火山视频三类标准路径，不能复制 relay、渠道和计费逻辑。

## 2. 明确不做

本阶段不做：

- 火宝自己的 API Key、Base URL、Provider 配置页面。
- 火宝自己的计费、额度、渠道选择和模型价格。
- 火宝自己的模型适配器。
- 新建消息队列、模型 Worker 或沙箱。
- 新建图片、视频模型网关或重复实现 Qunl relay。
- 复杂的幂等平台、媒体代理和多级模型网关。

图片和视频保留现有 Adapter，复用 Qunl 接口。Agent、图片、视频统一通过来源接口和当前用户身份调用，不新增重复网关。历史私有配置仅作为指定所有者的显式来源保留，不开放新增或修改凭据页面。

## 3. 模型来源

### 3.1 Qunl 是默认来源

普通用户使用 Qunl 返回的可用模型；指定旧数据所有者也可显式选择自己的历史私有配置。模型描述至少包含：

- 用途 `purpose`；
- 模型名称；
- 调用协议 `protocol`；
- 是否可用；
- 可选的展示名称和能力信息。

火宝不读取 Qunl 的 API Key、渠道 ID、Base URL 或内部配置详情。

用户“配置模型”的含义是：在 Qunl 权限范围内选择模型，不是在火宝里创建模型渠道。

### 3.2 最小接口

优先复用 Qunl 现有兼容接口，由 Qunl 内部转发入口完成用户身份映射。火宝不直接把浏览器 Session 或 API Key 传给公开 relay。

```text
GET  /internal/huobao/models?purpose=text
GET  /internal/huobao/models?purpose=image
GET  /internal/huobao/models?purpose=video
POST /internal/huobao/v1/chat/completions
```

接口只供火宝服务调用，不经过浏览器，不注册到普通用户 API 文档。

模型列表响应：

```json
{
  "data": [
    {
      "id": "模型名称",
      "name": "展示名称",
      "purpose": "text",
      "protocol": "openai_chat",
      "enabled": true
    }
  ]
}
```

模型能力与调用身份：

模型列表、生成、查询和取消复用 Qunl 当前账号及绑定 Token 的统一鉴权；模型列表与生成使用同一分组、模型限制、启用渠道和协议能力。通用 `/v1/models` 不是全部能力清单；不得按模型名前缀猜测协议。`protocol` 集中定义为 `openai_chat`、`openai_image`、`volcengine_video_v3`，可选能力只返回已知值。

Qunl 在现有用户设置中明确绑定火宝使用的现有 Token ID，验证归属与可用性。未绑定、账号不可用或 Token 失效直接报错，不挑选第一个可用 Token，不创建共享 Token，不为旧任务增加鉴权例外。已有视频仍按 `user_id + task_id` 复用 Qunl 既有任务服务，配置变化不能导致跨用户查询或重新提交。

`dreamina-seedance-2-0-mini-260615` 是已有实测成功的低成本视频验收候选，不是所有用户的硬编码默认值。未选择且无明确默认配置时提示选择，不静默切换。

Agent 调用请求：

```json
{
  "model": "模型名称",
  "messages": [],
  "stream": true,
  "temperature": 0.7,
  "metadata": {
    "source": "huobao",
    "agent_type": "script_rewriter",
    "huobao_task_id": "..."
  }
}
```

Qunl 负责校验当前用户是否可以使用该模型，并使用现有模型 API 完成调用。火宝只把请求和响应转换为 Mastra/AI SDK 或生成 Adapter 需要的格式。

图片和视频不另建一套内部协议，沿用现有兼容接口：

```text
POST /internal/huobao/v1/images/generations
POST /internal/huobao/v1/images/edits
POST /internal/huobao/api/v3/contents/generations/tasks
GET  /internal/huobao/api/v3/contents/generations/tasks/:id
```

调用身份、模型权限和额度仍由 Qunl 处理，火宝只负责把用户请求转换成现有 Adapter 能接受的格式，并保存自己的任务状态。

### 3.3 认证方式

浏览器到火宝仍使用现有 Qunl Session 代理和火宝签名身份。

火宝到 Qunl 沿用 v1 签名，与浏览器代理共用专用集成密钥和固定测试向量，不复用 Session Secret。签名覆盖：

- 协议版本；
- `user_id`；
- 请求方法和路径；
- 规范化查询串；
- 请求 ID；
- 时间戳。

不转发浏览器 Cookie、Authorization、`New-Api-User` 或 API Key。

内部模型入口统一校验签名、当前账号和绑定 Token，底层复用 relay 及既有任务服务；GET 查询和 DELETE 取消还须校验任务归属，不增加独立收尾身份或绕过 Token 检查的通道。首版依赖可信回环或容器网络，不增加请求体摘要、key_id、重放表或自动轮换，也不声称保护请求体或防重放。对外入口拒绝 `/internal/huobao/*`，只有路径名称不构成隔离。

客户端只请求配置好的 Qunl 地址和白名单路径，不向其他主机转发签名，不跟随跨主机重定向。跨不可信网络部署时须先调整传输保护。

另复用同一签名提供 `GET /internal/huobao/user-status`，已存在用户返回 `{ "enabled": true|false }`，不存在返回 404，查询异常返回错误，不依赖模型 Token。仅用于迁移所有者验证和历史来源每次模型调用前检查，只接受明确的 true，不缓存状态绕过禁用；普通 CRUD 不逐次追加状态查询。

## 4. 计费边界

火宝不做任何计费逻辑：

- 不计算价格；
- 不预扣额度；
- 不保存余额；
- 不写 Qunl Token；
- 不重复判断 Qunl 模型额度；火宝仍须检查用户归属、输入和并发/存储限制。

Qunl 自己完成现有的模型权限、额度和计费。火宝只处理调用成功、调用失败和任务状态。

火宝日志最多记录：

- `request_id`；
- `user_id`；
- Agent 类型；
- 模型名；
- 成功或失败；
- 耗时。

不记录完整 Prompt、请求正文、API Key 或上游返回正文。

## 5. 火宝模型配置

### 5.1 本地只保存选择结果

火宝可以保存用户当前选择的模型，但只保存以下内容：

```text
user_id
slot                 -- agent:注册表中的类型、image 或 video
source               -- qunl | legacy_private
purpose              -- text | image | video
model_name
protocol
legacy_config_id     -- 仅历史来源使用
updated_at
```

统一使用 `model_config_refs`，不再建设第二张 Agent 模型选择表：

```text
model_config_refs
  id + 上述字段
```

唯一约束：

```text
(user_id, slot)
```

这张表只保存选择，不保存 Key。Qunl 来源每次调用向 Qunl 校验；历史来源每次检查私有引用和 Qunl 账号状态。旧记录不能绕过来源权限或禁用。

### 5.2 现有 `ai_service_configs` 的过渡状态

当前代码已经有一组“Qunl 快捷配置”，它会把 Qunl API Key、Base URL 和模型写入火宝的 `ai_service_configs`。这条路径只用于本地联调和短期迁移，不代表正式接入完成。

Qunl 来源不读取旧配置；但用户已确认旧 Key 保留给指定所有者，规则为：

- 用 `HUOBAO_MIGRATION_OWNER_USER_ID` 指定归属并确认 Qunl 用户存在且启用；不由首个访问者认领，不硬编码用户 ID。
- 旧 Key、Base URL、模型和用途原值迁入带非空 `user_id` 的私有配置，不擅自换 Key、迁到 Qunl、停用或删除。
- `legacy_private` 来源只读接入；引用用 `(user_id, legacy_config_id)` 复合外键关联配置，协议显式登记，未知协议停止迁移。
- 只有所有者可显式选择已有配置，不开放新增或修改凭据页面；其他用户不能列出、读取、测试或调用。
- 不返回完整 Key，不写日志或清单；数据库与备份不进入仓库或公开目录，不新增独立密钥平台。
- 任一来源失败都直接报错，不自动跨来源切换。
- 每次模型调用前通过内部状态接口检查 Qunl 账号，包含 Agent 后续步骤和任务查询；账号不可用或检查失败就停止调用，不提供特殊收尾例外。

### 5.3 配置来源统一

Agent、图片和视频都使用同一个 `ModelConfigSource`：

```text
ModelConfigSource.list(context, purpose)
ModelConfigSource.resolve(context, selectionRef)
```

来源由用户选择记录确定，不由全局单一开关替所有用户决定。`resolve` 返回服务端调用描述和受限客户端，不向路由输出 Key；业务层按协议取已有 Adapter，不判断渠道、环境变量或具体来源。新增 Qunl 模型只调整 Qunl 配置与能力描述，不改 Agent、图片、视频业务。

## 6. Agent 运行方式

### 6.1 Agent 实例共享

所有用户共享同一套 Agent 代码和内置 Prompt/Skill。每次运行都创建独立的请求上下文：

```text
user_id
drama_id
episode_id
agent_type
model_name
request_id
用户自定义 Prompt/Skill 文本
```

Agent 本身不保存用户状态，工具层必须通过 `user_id` 查询和写入数据。

### 6.2 Prompt 和 Skill

- 内置 Prompt/Skill 只读；
- 用户 Prompt/Skill 只能保存为纯文本；
- 用户文本不能定义工具、命令、脚本或文件访问权限；
- 用户 Prompt/Skill 只影响当前用户的 Agent 输出；
- 工具权限和数据范围由火宝代码控制，不由 Prompt 决定。

### 6.3 调用失败

Qunl 返回模型不可用、用户无权、额度不足或上游失败时：

- 火宝直接显示明确错误；
- 不自动切换到其他用户模型；
- 不自动跨来源切换；显式选择自己的历史配置不属于回退；
- 不做静默重试。

## 7. PostgreSQL 范围

PostgreSQL 仍然是正式 Web 的数据库要求，但只处理火宝自己的业务数据：

- 项目、剧集、角色、场景、道具；
- 分镜、任务和媒体元数据；
- 用户 Prompt/Skill；
- 用户 Agent 模型选择；
- 运行状态和必要的指令版本/摘要；普通日志沿用应用日志，不新增审计表。

不把 Qunl 用户表、模型渠道表和计费表复制到火宝。

数据库约束：

- 用户业务表的 `user_id` 非空；
- 父表建立 `(user_id, id)` 唯一约束；
- 子表使用复合外键；
- 用户私有名称唯一约束包含 `user_id`；
- 查询、更新、删除都必须同时带 `user_id`。

SQLite 仅作为旧数据迁移输入。本地开发、集成测试和正式 Web 均使用 PostgreSQL。

## 8. 实施顺序

### 阶段一：冻结最小接口

- 冻结 Qunl 模型列表响应；
- 冻结 Qunl Agent 调用请求和流式响应；
- 冻结服务间签名；
- 冻结火宝用户模型选择表。

### 阶段二：切换 PostgreSQL

- 建立 PostgreSQL Schema；
- 增加 `user_id` 约束和索引；
- 通过双用户隔离测试；
- 完成 SQLite 到 PostgreSQL 的可恢复迁移方案。

### 阶段三：接入 Qunl 模型来源

- 统一内部路径、v1 签名、按用途模型描述和明确 Token 绑定，复用既有 relay；
- 火宝实现 `QunlModelSource`；
- 增加只读历史私有来源并验证显式归属，不强制迁 Key；
- Agent、图片和视频统一使用该来源；
- 设置页只显示可用模型选择，不显示 API Key。

### 阶段四：验收

- 用户 A、B 的项目和 Agent 工具完全隔离；
- 用户 A 不能读取用户 B 的模型选择；
- Qunl 来源的 Agent 调用进入 Qunl；显式历史来源只使用所有者原配置；
- 火宝日志没有 API Key、完整 Prompt 和请求正文；
- Qunl 模型禁用后，火宝下一次调用立即失败；
- PostgreSQL 约束和迁移测试通过。

## 9. 完成标准

1. Qunl 来源不读取或保存长期 Key；历史 Key 原值保留给指定用户，其他用户不可用。
2. 新用户模型和 API 由 Qunl 提供，两类来源失败都不自动切换。
3. 文本、图片和火山视频复用 Qunl 现有兼容接口，不新增重复网关。
4. 火宝不包含计费、余额、价格和渠道选择逻辑。
5. Agent 代码共享，但请求上下文和业务数据按用户隔离。
6. 用户 Prompt/Skill 仍然只能作为纯文本补充。
7. PostgreSQL 双用户隔离和迁移测试通过。

## 10. 审查结论

方案保留已有兼容接口，不新增模型网关、计费平台或沙箱。需要落实默认拒绝的租户数据层、PostgreSQL、明确调用身份、按协议适配和完整业务验收，不能把公网协议测通说成 SaaS 已完成。

### 10.1 素材与任务验收边界

参考素材先校验当前用户资产归属再读字节，图片保留已有 multipart 接口。视频参考图、data URL 兼容性及素材上传接入放到下一阶段设计和实测，不作为本阶段隔离验收前提；现有成功记录只证明文生视频，不能标记参考图已验证。未验证的视频参考入口本阶段不开放，不发送需 Cookie 的私有地址、不公开目录、不静默遗漏素材，本地不新增域名和证书。

结果下载受允许目标、大小和时长限制，写入当前用户目录成功才标记完成；失败不把临时远程 URL 当作永久资产，不接受任意客户端 URL 作为下载入口。

Agent、HTTP 和 FFmpeg 取消必须停止本地执行。上游视频取消复用 Qunl 现有 DELETE 和 Adapter 能力判断，确认取消或终态才释放；不支持或结果未知时保留 ID 和占用，正常鉴权下查到终态才释放，本地停止采用结果不等于上游终止。鉴权失败就停止本轮查询并标记待核对，不提供特殊通道；恢复有效账号及 Token 后可显式恢复原 ID 查询，不重新提交。任务显示状态与占用分开，用 `released_at` 标记是否释放；失联任务核实后由运维处理，不按超时猜测。重启只恢复已有 ID 的正常鉴权查询，中断的 Agent/FFmpeg 不自动重跑，迟到回调不得覆盖终态。

任务准入使用主设计第 21.7 节的 PostgreSQL 行锁，原子检查用户及全局占用；单实例文件写入按用户互斥并逐块限制未知长度下载，字幕、缩略图、海报、FFmpeg 输出和临时文件同样受限。上传在解析前限制实际字节和用户级/全局在途数量，图片设像素上限；不得只在环境变量写上限或全部读入内存后才检查。

账号生命周期按 Qunl 现有规则，禁用后拒绝访问和模型调用。三种删号入口共用按用户清理流程：先禁用，停止火宝本地执行及轮询，再清理该用户数据，成功后完成 Qunl 原有删除；本地未停止或清理失败返回错误并允许重试，不等待上游终态，也不声称上游已取消。不处理删号与在途普通请求的特殊竞态，不增加操作门闩、清理标记或重新启用互斥。

本阶段须由两个真实 Qunl 用户在火宝完成 Agent 工具写入、图片、低成本文生视频、落盘和预览，并验证流式、图片参考图、下载和合并。视频参考图另在下一阶段接入和验收，不阻塞本阶段隔离完成，也不标记为已验证。公网直测不能替代本阶段双用户业务验收；自动化和桌面/移动浏览器验收通过后才开放对应入口。
