# 火宝 Web 接入 Qunl 账号与多租户隔离设计

日期：2026-10-16

修订：2026-10-18。本设计描述目标状态，不代表部署和完整业务验收完成。第 3 节记录改造前基线；实际进度见执行计划第 16.4 节。

本轮范围：保留原模型配置与公开接口调用，按用户隔离；不建设内部模型入口、Token 绑定、双来源、复杂取消恢复或删号联动。保留并发、存储、上传限制及基本超时；视频参考素材下一阶段处理。

文档关系：本文件是隔离规则的主依据；模型简化设计细化调用契约；执行计划逐项落实。重型模型网关历史稿不再执行。冲突须同步修正文档，不长期保留两套规则。

## 1. 目标

将火宝改造成只提供 Web 服务的多用户应用，并复用 Qunl 现有账号体系。

本次设计解决四件事：

1. 火宝不再提供注册和独立登录，用户身份由 Qunl 提供。
2. 每个用户的项目、资产、任务、模型配置和个性化设置严格隔离。
3. 所有用户共享火宝内置 Agent 能力，但 Agent 每次运行只能访问当前用户的数据。
4. 用户可以配置自己的 Prompt 和 Skill，但它们只能是文本指令，不能上传或执行脚本、代码和插件。

桌面端不在本次范围内。现有 Electron 代码暂不删除，Web 版不再依赖桌面端的数据目录、迁移和更新能力。

## 2. 已确认需求

- 只完善 Web 版。
- Qunl 是唯一账号来源，火宝不开放注册。
- 测试阶段使用本地 HTTP 和端口，不要求域名与证书。
- 正式部署预计位于同一域名下，由 Qunl 统一入口转发。
- 用户的项目、剧集、角色、场景、道具、分镜、媒体文件、生成任务、模型配置和个人 Agent 配置必须隔离。
- 火宝内置 Prompt 和 Skill 保留并默认生效。
- 用户可以补充自己的 Prompt 和 Skill。
- 用户自定义内容只允许纯文本，不支持文件包、引用文件、脚本、命令或可执行代码。
- 不引入容器沙箱、虚拟机沙箱或按用户启动独立 Agent 进程。

## 3. 当前系统问题

火宝当前按单用户本地软件设计：

- 所有接口没有登录鉴权。
- 所有业务数据存放在同一个 SQLite 数据库中，业务表没有用户归属字段。
- 多数读取和修改只按数字 ID 查询，知道 ID 即可能访问其他数据。
- 所有上传图片、生成图片和视频共用一个 `data/static` 目录。
- AI 模型配置和 API Key 全局共享，接口还会把完整 Key 返回前端。
- Agent Prompt 和 Skill 位于同一个可写 workspace，修改后影响所有用户。
- Agent 工具只按 `drama_id`、`episode_id` 或资源 ID 查询，没有验证资源属于当前用户。

因此，仅在页面前面增加登录检查不能形成租户隔离。隔离必须落实到身份传递、数据库查询、文件路径和 Agent 工具四个层面。

## 4. 方案比较

### 4.1 每个用户独立数据库和目录

每个用户拥有一份 SQLite 数据库和独立数据目录。

优点是物理边界清楚，单次查询不需要附加用户条件。缺点是连接管理、数据库迁移、备份、统计、任务调度和故障排查都会随着用户数量增长而明显复杂。

不采用。它更适合少量大客户的独立部署，不适合现有 Qunl 用户共享一套 Web 服务。

### 4.2 共享数据库，所有租户表增加用户 ID

所有用户共享数据库和应用进程，每条用户数据都带 `user_id`，所有读写强制附加当前用户条件。媒体文件按用户目录存放。

优点是结构简单、运行成本低，适合当前代码规模；缺点是必须系统性改完所有查询，遗漏一处就可能造成越权。

采用此方案，并用统一数据访问入口、复合索引、自动化越权测试和 Agent 工具校验降低遗漏风险。

### 4.3 将火宝业务表直接合并进 Qunl 数据库和 Go 服务

账号和业务数据都由 Qunl 管理，火宝仅保留前端。

这种方式最终边界最少，但需要把现有 TypeScript、Hono、Drizzle、Mastra 和生成任务逻辑大规模迁移到 Go，改造风险和周期远超本次目标。

不采用。火宝继续作为独立业务服务，只引用 Qunl 用户 ID，不直接读取 Qunl 用户表。

## 5. 总体架构

采用“Qunl 认证入口 + 火宝独立业务服务 + 共享租户数据库”的结构。

```text
浏览器
  |
  | Qunl 登录 Cookie
  v
Qunl API /huobao/* 反向代理
  | 1. 验证 Qunl 登录状态和用户状态
  | 2. 删除浏览器传入的所有 X-Qunl-* 头
  | 3. 注入带签名的用户身份
  v
火宝 Web 服务
  | 1. 验证签名和时间
  | 2. 建立 RequestTenantContext
  | 3. 所有数据库、文件和 Agent 操作使用该上下文
  v
火宝数据库 + data/users/{user_id}/static
```

本地测试仍使用同一入口模式：Qunl 监听一个端口，火宝监听另一个仅供内部转发的端口。浏览器只访问 Qunl 入口，不直接访问火宝后端端口。

### 5.1 Qunl 模块入口

Qunl 现有 Web 控制台已经具备侧栏模块配置能力。新增普通用户可见的“火宝短剧”模块，模块键使用 `huobao`，放在控制台区域，图标使用现有的 `Clapperboard`。

管理员可以全局启用或停用该模块；启用后默认对用户显示。是否允许用户在个人侧栏设置中隐藏，沿用 Qunl 现有模块规则，不另建权限系统。

点击模块后整页访问 `/huobao/`，不使用 iframe，也不把火宝页面改写成 Qunl React 路由。Qunl 当前侧栏使用 React Router 的 `Link`，而 `/huobao/` 属于后端反向代理路径，因此该菜单项必须使用普通 `<a href="/huobao/">` 或 `window.location.assign('/huobao/')` 发起真实页面请求，否则前端路由会落入 Qunl 的 404 页面。

用户从火宝返回 Qunl 时访问 `/console`。两个页面位于同一站点下，用户只登录一次。

### 5.2 Qunl 反向代理

Qunl Go 服务新增 `/huobao` 和 `/huobao/*path` 路由，并在 Web 的兜底路由之前注册。代理将外部路径的 `/huobao` 前缀去掉后转发给火宝，例如：

```text
/huobao/                         -> http://127.0.0.1:5679/
/huobao/api/v1/dramas           -> http://127.0.0.1:5679/api/v1/dramas
/huobao/static/images/a.png     -> http://127.0.0.1:5679/static/images/a.png
```

火宝前端构建时设置 `NUXT_APP_BASE_URL=/huobao/`。现有 Nuxt 配置、API 地址和媒体地址已经支持此前缀，不需要在 Qunl 中嵌入火宝前端代码。

代理路由使用火宝专用 Session 鉴权，不能直接套用 Qunl 当前的 `UserAuth()`。现有 `UserAuth()` 还要求请求携带前端生成的 `New-Api-User` 头，而浏览器整页导航不会携带该头。专用中间件直接读取 Qunl Session，并重新确认用户存在且未禁用。

代理采用轻量规则，不增加独立认证中心：

- 转发前删除浏览器传入的 `Cookie`、`Authorization`、`New-Api-User`、`X-Qunl-*`、`Forwarded` 和 `X-Forwarded-*`。
- 由 Qunl 写入新的可信身份头，火宝不能读取 Qunl Session Cookie。
- 火宝返回的 `Set-Cookie` 不向浏览器透传。
- 浏览器代理只放行页面、公共构建资源、普通业务 API 和认证媒体；拒绝 `/internal/*` 等内部维护路径，不能替浏览器签名调用清理接口。
- POST、PUT、PATCH、DELETE 校验 `Origin` 必须为当前可信 Qunl 站点，缺失或 `null` 同样拒绝，不信任客户端转发头；不增加单独 CSRF Token 系统。
- 本地 HTTP 允许 Session Cookie 不带 `Secure`；正式 HTTPS 部署必须启用 `Secure`。

火宝服务只监听 `127.0.0.1` 或容器内部网络。浏览器不能绕过 Qunl 直接访问火宝端口。

## 6. 身份传递

### 6.1 Qunl 侧

新增火宝专用会话认证中间件。它直接验证 Qunl Session Cookie、用户是否存在以及账号是否启用，不依赖浏览器提供 `New-Api-User` 请求头。

认证成功后，反向代理注入：

- `X-Qunl-Auth-Version: 1`
- `X-Qunl-User-Id`
- `X-Qunl-Timestamp`
- `X-Qunl-Request-Id`
- `X-Qunl-Signature`

签名使用单个独立密钥 `HUOBAO_PROXY_SECRET`，覆盖协议版本、用户 ID、方法、去掉 `/huobao` 前缀后的规范化路径和查询串、时间戳、请求 ID。火宝按自己收到的请求目标重算，双方采用相同路径形式，不复用 Qunl Session Secret。

签名允许很短的时间误差，过期后拒绝。第一阶段不实现请求 ID 去重、密钥版本和自动轮换；火宝只监听内部地址，因此这里用于确认请求来自 Qunl，不承担公网级网关功能。

代理必须先删除客户端请求中的同名头，再写入可信值。否则浏览器可以伪造身份。

### 6.2 火宝侧

火宝增加全局认证中间件：

- 缺少身份头：返回 401。
- 签名错误：返回 401 并记录安全日志。
- 时间戳超过允许误差：返回 401。
- 验证成功：将 `userId` 和请求 ID 写入 `RequestTenantContext`。

所有 `/api/v1/*`、用户媒体文件和生成结果访问都必须经过该中间件。健康检查只返回存活状态，不包含用户数据，可以保留为内部免登录接口。

正式环境中火宝端口只监听回环地址或容器内部网络，不能直接暴露公网。

## 7. 数据隔离模型

### 7.1 租户标识

使用 Qunl 用户表的整数 ID 作为火宝的 `user_id`。火宝不复制密码、邮箱、配额等账号资料，也不创建独立用户账号。

### 7.2 用户数据表

以下表增加非空 `user_id`：

- `dramas`
- `episodes`
- `characters`
- `scenes`
- `props`
- `storyboards`
- `episode_characters`
- `episode_scenes`
- `episode_props`
- `storyboard_characters`
- `storyboard_props`
- `assets`
- `sys_task`
- `agent_tasks`
- `video_merges`
- `ai_service_configs`（各用户保存自己的 Key、Base URL、模型、协议和用途，不新增来源或选择表）
- `app_settings`（主键为 `(user_id, key)`）
- 用户自定义 Prompt 表
- 用户自定义 Skill 表

即使子表可以通过父表推导用户，也保留 `user_id`。这样直接按子资源 ID 查询、轮询任务或执行 Agent 工具时，可以在同一条 SQL 中完成归属验证，避免先查询再判断产生遗漏。

数据库同时建立租户复合约束，避免只靠业务代码维持关系：

- 父表为 `(user_id, id)` 建立唯一约束。
- 子表使用 `(user_id, drama_id)`、`(user_id, episode_id)` 等复合外键引用父表。
- 关联表的两端都必须通过复合外键证明属于同一用户。
- 用户私有字段原有唯一约束改为包含 `user_id`，例如 `(user_id, name)`。
- 常用列表、详情和任务查询建立以 `user_id` 开头的复合索引。

数据库迁移测试必须验证约束真实生效，不能只验证应用接口返回正确。

### 7.3 共享数据表

以下内容为系统级共享数据：

- AI 服务提供商定义 `ai_service_providers`
- 内置风格预设
- 内置 Prompt
- 内置 Skill
- Agent 类型和可用工具定义

内置内容只允许管理员通过代码发布更新，普通用户不能修改。

风格预设如继续允许用户新增，则采用“系统预设只读 + 用户私有预设”的形式。用户创建的预设带 `user_id`，查询时返回系统预设和当前用户预设的并集。

### 7.4 查询规则

任何用户资源的读取、更新和删除必须在数据库语句中同时包含资源 ID 与 `user_id`：

```text
WHERE id = :resource_id AND user_id = :current_user_id
```

禁止采用“先按 ID 查询，再在业务代码中比较用户 ID”的常规写法。更新和删除必须直接使用复合条件，并检查受影响行数。

跨用户资源统一表现为 404，不向请求者透露该 ID 是否真实存在。

普通 CRUD 的单资源更新/删除零行按 404 处理，内部幂等清理已不存在的数据返回成功。用户设置等复合主键表按完整主键及用户范围查询，不额外强制数字 ID。

### 7.5 数据访问边界

路由不能直接自由拼接 Drizzle 查询。增加按领域划分的租户数据访问模块，例如：

- `tenantDramas`
- `tenantEpisodes`
- `tenantAssets`
- `tenantTasks`
- `tenantAiConfigs`

全局任务准入、启动恢复、迁移和按用户清理是明确的内部维护操作，单独列出允许访问数据库的文件，并测试其范围。它们不能变成路由或 Agent 可任意调用的全局查询入口。

这些模块的所有公开函数第一个参数必须是 `TenantContext`，不存在不带用户范围的用户数据查询函数。后台 Agent 工具也调用同一层，不能绕过。

## 8. 文件与媒体隔离

文件目录改为：

```text
data/users/{user_id}/static/uploads/
data/users/{user_id}/static/images/
data/users/{user_id}/static/videos/
data/users/{user_id}/static/merged/
```

数据库中仍保存用户目录内的相对路径，例如 `static/images/abc.png`，不保存可由客户端控制的绝对路径，也不在响应中暴露服务器磁盘路径。

读取文件时，由后端根据当前 `user_id` 计算根目录并执行规范化检查。解析后的绝对路径必须仍位于该用户根目录内，否则立即拒绝，防止 `../` 路径穿越。

路径检查同时拒绝符号链接/目录联接绕出用户根目录，迁移同样检查，不只比较路径字符串。用户不能控制服务器根目录或文件名。

只接收业务允许且经过文件内容校验的图片、音频和视频格式；不能仅信任文件名或客户端 MIME。用户媒体响应设置 `X-Content-Type-Options: nosniff`，不把 HTML、SVG 或脚本作为同源可执行内容返回。Prompt/Skill 仍只接收文本字段，不新增文件上传能力。

媒体访问不能继续使用全局 `serveStatic({ root: DATA_ROOT })`。改为经过认证的用户媒体路由，由当前用户上下文决定实际目录。

私有媒体统一设置 `Cache-Control: private, no-cache`，每次读取重新经过授权；携带 Cookie 不会自动禁止公共缓存。只有带内容哈希的公共前端构建资源可以使用 `public, max-age=31536000, immutable`，入口 HTML 不使用长期缓存。

同一浏览器切换账号后不能读到上一账号缓存。媒体路由先授权，再处理条件请求和视频 Range 请求；不得从离线缓存返回上一账号的私有媒体。

包含用户数据的业务 API 和业务入口 HTML 使用 `Cache-Control: private, no-store`；前端账号变化时清除用户内存状态，不把项目或模型配置持久缓存成全站共享数据。

## 9. Agent 隔离

### 9.1 Agent 实例可以共享

四类 Agent 可以继续作为进程级共享实例：

- 剧本改写
- 资产提取
- 分镜拆解
- 提示词生成

Agent 实例本身不保存用户业务状态。每次调用通过 Mastra `RequestContext` 注入：

- `userId`
- `dramaId`
- `episodeId`
- 当前用户选择的模型配置 ID
- 内容语言
- 本次启用的用户 Prompt/Skill 文本

共享 Agent 不等于共享用户数据。真正的隔离由工具层完成。

### 9.2 Agent 工具必须强制校验归属

每个工具读取或写入前都必须取得 `userId`。例如保存角色提示词时，不能只按 `character_id` 更新，而应同时限制：

```text
character_id = :id AND drama_id = :drama_id AND user_id = :user_id
```

Agent 启动前还要一次性验证：

- `dramaId` 属于当前用户。
- `episodeId` 属于当前用户。
- `episodeId` 确实属于给定的 `dramaId`。
- 指定模型配置属于当前用户且已启用。

工具权限不依赖 Prompt。即使用户文本要求“读取其他用户项目”或模型生成了错误 ID，数据库操作仍必须拒绝。

### 9.3 不给 Agent 运行时文件系统写权限

当前 Agent 挂载了一个可写 Mastra `LocalFilesystem` workspace。Web 多租户版本不需要 Agent 自己创建或修改文件，因此运行时 Agent 不再挂载可写 workspace。

内置 Skill 由服务端以只读方式加载并拼入 instructions；用户 Skill 从数据库读取并作为文本拼入。Agent 不获得 shell、命令执行、脚本执行、任意文件读取或写入工具。

这使系统不需要引入重型沙箱。没有可执行能力，就没有“隔离用户脚本运行环境”的需求。

## 10. Prompt 与 Skill 设计

### 10.1 指令层级

每次 Agent 请求按以下顺序组合：

1. 系统不可变约束：工具边界、数据范围、必须遵守的输出结构。
2. 火宝内置基础 Prompt。
3. 火宝内置 Skill。
4. 当前用户启用的补充 Prompt。
5. 当前用户启用的补充 Skill。
6. 内容语言要求与最终不可变约束。

用户配置是补充层，不直接替换系统约束和内置生产流程。这样可以让用户改变文风、节奏、镜头偏好、角色描述习惯等，同时保留火宝正常工作所需的工具调用和字段格式。

### 10.2 用户 Prompt

每个用户可为每类 Agent 保存一份补充 Prompt：

- `user_id`
- `agent_type`
- `content`
- `enabled`
- `updated_at`

同一用户和 Agent 类型只保留一份当前配置。内置 Prompt 单独展示为只读内容，用户界面明确标注自定义内容是“补充要求”。

### 10.3 用户 Skill

用户 Skill 是结构化的文本规则，不是上传的 `SKILL.md` 文件包：

- `id`
- `user_id`
- `agent_type`
- `name`
- `description`
- `content`
- `enabled`
- `sort_order`
- `created_at`
- `updated_at`

允许用户新增多条、启用、停用、排序和编辑。只接受 UTF-8 文本；不接受附件、目录、脚本、二进制、远程引用和可执行入口。

Skill 内容可以使用 Markdown 书写，但 Markdown 只作为文本格式，不解析代码块并执行。

### 10.4 输入限制

为了避免无限上下文和意外费用：

- 用户 Prompt 设置明确字符上限。
- 单条 Skill 设置明确字符上限。
- 每个 Agent 可启用的 Skill 数量设置上限。
- 保存时计算总字符数，超过上限直接拒绝，不做自动截断。
- 不使用关键词过滤判断“是否安全”，因为真正权限由工具层保证。

用户 Prompt/Skill 可能降低本人产出质量，但不能扩大工具权限或数据范围。

## 11. 用户模型配置

保留原有设置页与 `ai_service_configs`，每个用户保存自己的 Key、Base URL、模型、用途、协议、优先级、启用状态和可选温度。所有操作通过 `data/tenant/model-configs.ts`，按可信用户 ID 查询，不建设 Token 绑定、模型能力目录或双来源。

- 列表、详情、创建响应不回显 Key，只返回 `has_api_key`。编辑 Key 留空不提交，保留原值；新增必须提供 Key，显式空 Key 拒绝。
- 测试、读取、更新、删除和执行均限定本人配置，跨用户统一 404。客户端不能覆盖用户归属。
- 用途与协议由集中规则验证；更新在行锁内检查最终组合。被剧集引用的配置不能删除或改用途，可以停用。
- 显式配置失效、停用或用途不匹配直接失败，不回退默认 Key；未显式选择时沿用本人优先级和剧集锁定规则。
- 选项用配置 ID 与模型名区分，同协议同模型但不同 Key 不合并。
- 不新增密钥加密轮换平台；数据库和备份按含密钥数据保护，不进仓库、公共目录或日志。连通性测试不返回上游正文。

业务只依赖配置数据模块和协议 Adapter，新增协议不需要按用户写分支。Key 的有效性、模型权限和额度由 Qunl 公开接口负责，火宝不重复验证 Token 所有权。

### 11.1 复用现有 Qunl 兼容接口

Qunl 已经提供火宝所需的主要模型接口，首版直接复用，不重复建设图片、视频模型网关：

| 能力 | Qunl 接口 | 火宝调用约定 |
| --- | --- | --- |
| 文本 | `/v1/chat/completions` | Agent 使用当前用户保存的配置 |
| 图片 | `/v1/images/generations`、`/v1/images/edits` | 文生图和参考图统一走 `/v1` 兼容接口 |
| 火山视频 | `/api/v3/contents/generations/tasks`、`/api/v3/contents/generations/tasks/:id` | 创建和轮询直接使用 Qunl 火山兼容接口 |

Base URL 由用户配置，已有 URL 函数集中追加公开协议前缀，不重复拼接，不默认增加厂商目录。火山视频统一使用 v3，不按 Dreamina/Doubao 模型前缀切换旧接口。

Qunl Session 代理签名只用于登录身份；模型调用使用用户保存的 Key，不转发 Cookie 或身份签名。Qunl 启动不再注册旧内部自动选 Token 模型入口，既有公开 relay 负责权限、路由和计费。协议测通不等于完整业务验收。

## 12. 用户设置

当前全局 `app_settings` 改为用户设置，至少包括内容语言。主键应为 `(user_id, key)`。

没有用户设置时使用代码内明确默认值；不读取其他用户或旧全局行作为兜底。

系统级配置应放入独立的系统设置来源，避免与用户设置混在同一读写接口。

## 13. 接口行为

- 所有业务 API 默认要求登录。
- 未登录或身份签名错误返回 401。
- 当前用户无权访问的资源返回 404。
- 参数错误返回 400。
- 模型配置缺失或禁用时明确报错，不自动切换到别人的配置或未知默认配置。
- 后台任务记录创建时立即写入 `user_id`。
- 任务轮询、取消、删除和结果读取均按 `user_id + task_id` 查询。
- 管理员不会因为 Qunl 角色较高就自动读取用户作品。未来如需客服查看，必须增加独立、可审计的管理员接口。

### 13.1 轻量资源限制

数据隔离之外增加必要的用户级资源限制，但不建设复杂计费和调度平台：

- 限制每个用户同时运行的 Agent 数量。
- 限制每个用户同时运行的图片、视频和 FFmpeg 任务数量，并设置全局运行上限。
- 保留基本执行超时。本地失败、超时或重启中断结束本地工作并释放本地名额，保留上游 ID，不自动重提付费请求，不声称上游已停止。复杂取消和自动恢复本轮不做。
- 限制单个用户可使用的媒体存储空间。
- 上传解析前限制请求总字节数，同时限制用户级及全局在途上传数量；图片解码设像素上限。无 `Content-Length` 的分块请求同样计数，不等全部读入内存后才校验。
- HTTP 请求频率优先复用 Qunl 已有的限流能力。
- 第一阶段不增加队列和 Worker。按任务类型取得 PostgreSQL 准入锁后，在同一事务中统计用户和全局占用并创建任务，达到上限就拒绝。普通事务中“先 count 再 insert”不够，必须防止并发超发。
- 第一阶段只运行一个火宝后端实例。文件写入按用户串行检查当前大小和新增字节，流式写入设上限；不引入存储配额平台。

具体数值通过环境变量配置，并给出保守默认值。超过限制直接返回明确错误，不静默降级或自动借用其他用户额度。

### 13.2 日志与账号状态

使用现有应用日志输出简易结构化记录，不增加独立审计平台。至少记录 `request_id`、`user_id`、请求方法、路径、状态码、耗时，以及后台任务 ID、类型和最终状态。日志不记录 API Key、完整 Prompt、Skill 内容或模型请求正文。

账号生命周期完全以 Qunl 为准，火宝不建立用户账号表和独立状态机：

- Qunl 用户正常时可以访问火宝。
- Qunl 用户被禁用或删除后，代理立即拒绝新的火宝请求。
- 模型请求用本次用户配置调用 Qunl 公开接口；失败就记录并结束本地任务，不换 Key、不重提，不把查询失败当上游取消。
- 在途任务不逐步查询账号状态，不增加失效 Token 收尾通道。账号禁用阻止新访问，不承诺立刻终止已经提交的上游任务。
- Qunl 删除流程不等待火宝，也不增加火宝用户状态表、删除联锁或同步资产清理。旧资产留存与清理不作为本阶段交付承诺，后续删除文件仍须明确授权。

## 14. 迁移策略

现有火宝数据库没有用户归属，不能自动猜测旧数据属于谁。

迁移规则：

1. 空 PostgreSQL 数据库直接创建带 `user_id` 和复合约束的新结构。
2. 非空旧 SQLite 数据库迁移时必须显式提供 `HUOBAO_MIGRATION_OWNER_USER_ID`。
3. 未提供归属用户时迁移立即失败，不启动业务服务。
4. 创建迁移记录，状态依次为 `pending`、`files_copied`、`database_imported`、`completed`。
5. 停止旧服务写入，将旧 `data/static` 复制到同盘临时用户目录，逐项校验相对路径、大小和 SHA-256；失败时不修改正式目录。
6. 在 PostgreSQL 单个事务中导入旧业务数据、补齐用户 ID、重置自增序列，并验证行数、子表关系和复合约束。
7. 数据库提交后将临时用户目录原子重命名为正式目录，再写入完成状态。
8. 迁移命令必须可重复执行：已完成步骤跳过，未完成步骤继续，不重复插入数据。
9. 旧 SQLite 数据库和旧文件保留，不自动删除；后续经明确确认再清理。
10. 迁移运行 ID、源清单和目标所有者固定。数据库导入与 `database_imported` 标记同事务提交；重启按标记与清单识别已完成的目录重命名，遇到冲突停止，不覆盖已有用户目录。
11. 旧 Key、Base URL 和模型按原值导入所有者私有配置，不自动换 Key、改地址或写入 Qunl；见第 21.4 节。
12. 首版仅支持已知单用户源到空目标业务库的离线迁移，schema 与系统预设可预先建立；已有目标业务数据时停止，不自行合并或重编号。

该方案不会启发式猜用户，也不会把旧数据默认归给第一个登录用户。

## 15. 数据库选择

本地开发、测试和正式部署统一使用 PostgreSQL，不再把 SQLite 作为新版 Web 多用户模式的运行数据库。这样可以在开发阶段直接验证真实的并发写入、复合外键和迁移行为，避免上线前再次更换数据库驱动和查询实现。

第一阶段依靠应用层 `user_id` 条件、复合外键、唯一约束和越权测试保证隔离，不启用 PostgreSQL RLS，避免增加连接上下文和调试复杂度。未来用户量增加后可以评估 RLS 作为第二层保护，但不能替代应用层授权检查。

现有 SQLite 仅作为旧数据迁移来源，迁移完成后不参与业务读写。

切换 PostgreSQL 不是只修改连接字符串。实施时必须一并替换 `better-sqlite3` 和 Drizzle SQLite schema，清理 `PRAGMA`、同步 `.get()/.run()`、`lastInsertRowid`、`changes`、SQLite DDL 以及数据库文件容量统计等 SQLite 专用逻辑。业务查询继续使用 Drizzle，但统一改为异步 PostgreSQL 调用。

## 16. 测试与验收

至少创建用户 A 和用户 B，覆盖以下测试：

### 16.1 身份

- 已登录用户点击 Qunl 的“火宝短剧”模块后可以直接进入，不出现第二次登录。
- 未登录用户访问 `/huobao/` 时由 Qunl 拒绝或跳转登录页。
- 未登录不能访问火宝业务页面、API 和媒体。
- 浏览器伪造 `X-Qunl-*` 请求头无效。
- 过期签名和错误签名被拒绝。
- 被 Qunl 禁用的用户不能继续访问。
- 直接访问火宝内部端口不可用。
- `/huobao/api/v1/*` 和 `/huobao/static/*` 均能正确去掉前缀后转发。
- 代理不会把 Qunl Cookie、客户端身份头或火宝 `Set-Cookie` 透传到错误方向。
- 非当前站点发起的写请求被 `Origin` 校验拒绝。

### 16.2 数据

- A 创建的项目不出现在 B 的列表中。
- B 使用 A 的项目、剧集、角色、分镜、任务和配置 ID 请求时全部返回 404。
- 更新、删除和批量接口同样隔离。
- 关联表不能把 A 的资源绑定到 B 的项目。
- 直接绕过业务层写入跨用户父子关系时，PostgreSQL 复合外键拒绝。
- 两个用户可以分别创建仅在自己范围内要求唯一的同名数据。

### 16.3 文件

- A 不能读取、覆盖或删除 B 的媒体文件。
- `../`、绝对路径、编码后的路径穿越请求被拒绝。
- 数据库中的相对路径只能在当前用户根目录解析。
- 私有媒体响应为 `Cache-Control: private, no-cache`；同一浏览器切换 A/B 账号后不能读到上一账号缓存，条件请求和 Range 请求同样授权。

### 16.4 Agent

- A 的 Agent 只能读取和修改 A 的剧集与资产。
- 在用户 Prompt 中要求访问 B 的数据仍然失败。
- 模型返回其他用户资源 ID 时，工具层拒绝写入。
- 并发运行 A、B 的 Agent 时，请求上下文不会串用户。

### 16.5 Prompt、Skill 与模型配置

- A 的自定义 Prompt/Skill 不影响 B。
- 禁用用户 Skill 后不再注入。
- 超过字符或数量上限直接拒绝。
- 用户不能上传脚本或附件。
- API 列表不返回完整模型 Key。
- A 不能测试或使用 B 的模型配置。

### 16.6 迁移

- 非空旧库缺少迁移用户 ID 时启动失败。
- 指定归属用户后，数据行数、关系和文件均保持一致。
- 迁移失败时数据库事务回滚，旧文件不删除。
- 文件复制或数据库导入中断后，再次执行能够从迁移记录继续且不产生重复数据。

### 16.7 资源限制与账号状态

- 单个用户达到 Agent、生成任务或存储上限后被明确拒绝，不影响其他用户。
- 本地执行结束、失败或重启中断后释放本地名额；保留上游 ID，不重提请求，不把停止轮询显示成上游已取消。
- 并发请求不能突破用户级或全局限额；并发文件写入不能突破用户存储上限。
- 超大、分块和并发上传在解析前受限；图片像素超限拒绝；字幕、缩略图、海报、FFmpeg 临时输出同样计入存储限制，超限不得发布截断媒体。
- Qunl 禁用用户后不能再进入火宝或创建任务。
- 无效 Key 的模型调用明确失败，不换其他 Key、不自动重提；跨用户任务查询失败。
- Qunl 删除或禁用后拒绝新访问；本阶段不增加删号联动、在途账号状态查询或同步资产清理验收。

## 19. 设计依据

- AWS 将共享表加租户标识定义为 pooled data partitioning，并强调数据分区不等于租户隔离，应用仍需显式阻止跨租户访问：[AWS SaaS Architecture Fundamentals - Data partitioning](https://docs.aws.amazon.com/whitepapers/latest/saas-architecture-fundamentals/data-partitioning.html)
- OWASP 建议默认拒绝，并在每个请求上校验权限；授权执行点应靠近被保护资源：[OWASP Authorization Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Authorization_Cheat_Sheet.html)、[OWASP Authorization Patterns](https://cheatsheetseries.owasp.org/cheatsheets/Authorization_Patterns_Cheat_Sheet.html)
- PostgreSQL RLS 可以在未来作为共享表的数据库级第二层防护，且无匹配策略时默认拒绝：[PostgreSQL Row Security Policies](https://www.postgresql.org/docs/current/ddl-rowsecurity.html)
- Mastra Workspace 将文件系统、命令执行和 Skill 视为独立能力；脚本执行需要显式 Sandbox。本设计不配置 Sandbox，也不向用户开放文件型 Skill，从而将用户能力限制为文本指令：[Mastra Workspaces](https://mastra.ai/blog/introducing-mastra-workspaces)、[Mastra Filesystem Skills](https://mastra.ai/blog/introducing-filesystem-skills)

## 20. 最终决策

本项目采用：

- Qunl Session 认证和签名反向代理。
- 火宝独立业务服务和独立数据库。
- PostgreSQL 共享表的 `user_id` 行级隔离、复合外键和复合索引。
- 用户文件目录隔离和私有缓存策略。
- 共享无状态 Agent 实例。
- Agent 工具层强制用户归属校验。
- 内置只读 Prompt/Skill + 用户私有文本扩展。
- 保留原模型配置页，用户私有 Key、Base URL、模型与协议；直接调用 Qunl 公开接口，无自动选 Token 或双来源。
- 简单的用户级和全局并发、超时和存储限制。
- Qunl 作为唯一账号状态来源，火宝只保留必要的结构化运行日志。
- 不引入用户
Docker Desktop encountered an unexpected error and needs to clos代码执行能力和重型沙箱。

这是当前改造量、运行复杂度和隔离强度之间最合适的方案。

## 21. 最终补充与冲突裁决

本节根据当前代码审查和已有接口实测补充，并与前文、模型简化设计、执行计划同步。这里描述宣布“火宝 SaaS 多租户隔离完成”的最低条件，不表示已实现，也不表示本轮重新执行了付费模型测试。

### 21.1 租户上下文必须默认拒绝

当前过渡实现中的 `scopedWhere`、`scopedValues` 缺上下文时会退化为无用户条件查询或写入。用户业务一律禁止这种行为；迁移使用独立命令和明确所有者，不能借业务函数的无上下文模式迁移。

最终规则：

- 所有用户数据访问函数必须显式接收 `TenantContext`，不能把租户条件做成可选项。
- 缺少 `user_id`、请求 ID 或租户上下文时立即抛错，不能返回全局数据，也不能写入 `user_id = null`。
- 用户业务代码不允许直接导入数据库连接。只有租户数据模块、系统数据模块，以及明确列入白名单的准入、恢复、清理和迁移模块可以访问数据库；维护模块不得向普通业务暴露全局 CRUD。
- 系统数据与用户数据使用不同函数。`systemOrTenantWhere` 只能用于已列入系统共享清单的风格、内置 Prompt 和内置 Skill，不能用于项目、资产、任务或用户设置。
- 所有更新、删除必须检查受影响行数。目标属于其他用户或不存在时统一返回 404。
- 内部幂等清理不受普通 CRUD 的零行 404 规则限制；资源已清理返回成功。复合主键表按完整主键和用户范围查询，不要求所有表额外增加数字 ID。
- 测试和开发环境同样执行这些规则，不能只在 production 开启。

因此，单纯在现有查询外包一层可选 `scopedWhere` 不算租户数据层完成。完成标志是业务路由、Service、Agent 工具中不再存在绕过租户数据模块的用户数据查询。

### 21.2 请求外任务的租户身份

HTTP 请求内可以使用 `AsyncLocalStorage` 辅助传递身份，但后台任务不能只依赖隐式上下文。Promise、定时器、轮询、FFmpeg 回调、Agent 异步任务和服务重启后恢复任务都必须使用任务记录中保存的明确用户 ID。

统一流程：

1. 创建任务时在同一业务操作中写入 `user_id`、任务类型、目标资源 ID 和状态。
2. 启动异步逻辑时传入不可变的 `TenantContext`，不从全局变量推断用户。
3. 轮询或恢复任务时先按 `user_id + task_id` 读取，再用该上下文执行后续查询、文件写入和模型调用。
4. 回写角色、场景、分镜、媒体路径和任务状态时继续使用同一个 `user_id`。
5. 找不到任务所属用户、目标资源与任务用户不一致或上下文丢失时，任务直接失败并记录简易日志，不能按资源 ID 裸查后继续。
6. 启动时专用维护模块将残留本地任务标记失败，保留上游 ID；不发网络、不恢复查询、不重新提交。普通业务函数不得无上下文批量更新任务。
7. 在途执行沿用创建时的用户上下文；迟到回调不得覆盖终态或重复发布结果。指令文本冻结，但不宣称完整模型配置快照已实现。

共享 Agent 实例只共享代码和内置指令，不共享 RequestContext、模型选择、Prompt、Skill、工具状态或任务状态。

### 21.3 关联写入必须验证两端归属

仅给关联表写入当前 `user_id` 不足以证明两端归属。创建角色与剧集、场景与剧集、分镜与角色、分镜与道具等关联前，同时验证用户归属和既有业务关系；同属一用户也不能跨不允许共享的项目或剧集关联。PostgreSQL 复合外键作为用户归属的第二层约束。

批量保存接口不能接受前端传来的任意对象后直接展开写入。允许更新的字段应明确列出，资源 ID、`user_id`、父资源 ID 和系统字段不能由请求体覆盖。

### 21.4 旧数据与旧 API Key 的归属

用户已明确现有旧配置归 Qunl 用户 1（root），提供的测试 Key 归用户 87；只读数据库核对确认该测试 Token 为 2054。归属已明确，不按首个访问者认领；root 原模型 Key 尚未逐项核对及真实迁移。

迁移规则补充如下：

- 使用 `HUOBAO_MIGRATION_OWNER_USER_ID` 明确旧项目、媒体、Prompt、Skill、用户设置和旧模型配置的归属。
- 未提供用户 ID、Qunl 中不存在该用户或用户已禁用时，迁移失败。
- 旧 API Key、Base URL、模型和用途原值保留，导入带非空 `user_id` 的私有历史配置。仅改变归属和访问边界，不擅自迁到 Qunl、替换、停用或删除 Key。
- 旧配置迁入同一 `ai_service_configs`，仅所有者可查看安全字段、编辑、测试和调用；不另设历史来源或只读特殊通道。
- 模型选择失败直接报错，不自动换 Key；新旧用户使用同一配置逻辑。
- 设置页保留原有新增和编辑，Key 不回显，留空保留原值；不查询 Qunl Token 表或每步账号状态。
- 测试 Key 只能保存给 87，不替换 root 旧 Key；素材令牌不作为旧模型凭据。运行代码不写死用户 ID。
- 不新增加密和轮换平台，但数据库、备份和迁移产物按含密钥数据保护，不能进入仓库或公开下载目录。
- 迁移日志只记录配置数量和目标用户 ID，不记录 Key 明文。

### 21.5 模型按配置协议调用公开接口

通用 `/v1/models` 列表不能作为文本、图片、火山视频三类能力的唯一来源。真实验证已经证明 `dreamina-seedance-2-0-mini-260615` 可以通过火山兼容接口成功生成，但未出现在此前读取的通用模型列表中。

不建设新的模型能力目录或 Token 绑定。用户填写模型和协议，Qunl 公开接口判断 Key、模型权限和额度。火宝启动只接受用户配置模式，旧内部自动选 Token 路由停止注册，保留文件但业务不可达。

- 文本：OpenAI 兼容 `/v1/chat/completions`。
- 图片：OpenAI 兼容 `/v1/images/generations`、`/v1/images/edits`。
- 视频：火山兼容 `/api/v3/contents/generations/tasks` 及 `/:id` 查询。

Adapter 根据显式协议选择路径，不按模型名前缀切换旧接口。Mini 模型是低成本候选，不是所有用户固定的运行模型。模型请求使用本人 Key；代理 v1 签名只用于登录身份，依赖可信内部网络，不增加重放表、key_id 或自动轮换，也不声称防重放。

参考素材始终先校验当前用户资产归属再读取，图片保留已有 multipart 接口。视频参考图、data URL 兼容性及相关素材上传接入放到下一阶段设计和实测，不作为本阶段隔离验收前提；现有实测只证明文生视频，不能标记参考图已验证。当前未验证的视频参考入口不开放，不向上游发送需 Cookie 的 `/huobao/static/*`，不公开用户目录，不静默忽略素材，本地测试不新增域名或证书。

### 21.6 用户设置、Prompt 与 Skill

`app_settings` 必须改为 `(user_id, key)`，内容语言属于用户设置。旧全局内容语言迁移给指定旧数据所有者，其他用户使用代码默认值。系统级设置放在独立表或环境配置中。

用户 Prompt 和 Skill 均为数据库中的纯文本扩展：

- 不上传文件，不读取用户目录，不解析并执行代码块。
- 不增加工具，不改变工具参数校验，不改变数据访问范围。
- 每次 Agent 运行按 `user_id + agent_type` 加载并冻结文本快照，运行中修改只影响下次任务。日志仅保存版本号或摘要，不记录正文。
- 内置 Prompt/Skill 只读并由代码版本管理；用户只能启用、禁用和编辑自己的补充文本。

### 21.7 轻量资源限制的落点

环境变量中存在限制数值不代表限制已经生效。Agent、图片、视频、FFmpeg 和存储写入必须在实际创建入口调用统一限制服务。

第一阶段不增加消息队列。为 Agent、图片、视频、FFmpeg 各预建一条系统准入锁记录；事务以 `READ COMMITTED` 锁定对应记录，再读用户和全局运行数并写入任务。锁只覆盖准入，不覆盖模型调用或文件处理，防止并发超发。

本地任务通过统一终态函数结束。本地失败、超时或重启中断释放本地执行名额，保留上游 ID，不恢复轮询、不自动重提，不展示为上游已停止。并发限制只计算火宝本地工作，不承诺约束失败后仍在上游运行的任务；上游限制和费用由 Qunl 负责。本轮不增加 `released_at`、取消、租约或失联核对平台，也不承诺复杂排队公平性。

单实例文件写入按用户互斥：重新统计已落盘字节，按新增字节检查限额，再写同盘临时文件并原子重命名。未知长度下载逐块限制，失败不发布半文件、不标记完成。字幕、缩略图、视频海报和 FFmpeg 派生输出也必须经同一受限写入接口，临时文件计入占用；不能由图片库或子进程直接写正式文件绕过检查。FFmpeg 使用可中止的限长输出流及兼容流式写入的封装参数，触及上限就终止，不把截断文件标记成功；发布前验证媒体完整性和浏览器播放。启动时先处理上次中断的临时文件，才开放写入口。

请求体、单文件、图片像素和在途上传数量在集中配置中设置。Qunl 代理和火宝入口在 multipart/JSON 解析前限制实际收到的字节，不能只检查 `Content-Length`；上传许可覆盖解析与保存，确保还没进入生成任务的请求也不能耗尽共享内存。

模型额度和计费继续完全由 Qunl 处理，火宝不复制余额、价格或扣费逻辑。

### 21.8 正式运行模式

正式 SaaS 模式必须满足：

- `NODE_ENV=production`。
- 配置 PostgreSQL `DATABASE_URL`，且运行代码不再导入 `better-sqlite3`。
- 配置代理签名密钥；模型地址和 Key 保存在各用户私有配置中。
- 火宝业务端口仅监听回环或容器内部网络。
- 所有业务页面、API 和媒体必须经 Qunl 代理进入。
- 首版只有一个火宝后端实例；Qunl 对外入口不开放内部模型和清理路径。
- 本地开发和集成测试也使用 PostgreSQL；SQLite 只允许作为迁移输入，不能作为多用户运行库。

Compose 必须声明 PostgreSQL、健康检查和迁移就绪条件，应用显式使用 production。历史 development + SQLite 镜像验收不能作为新版部署证据。

### 21.9 完成定义

同时满足以下条件，才可以宣布 SaaS 隔离完成并打开 Qunl 模块入口：

1. PostgreSQL Schema、复合外键、复合唯一约束和索引落地，应用不再运行于 SQLite。
2. 用户数据访问默认拒绝无租户上下文，业务代码不再直接访问数据库。
3. 所有 HTTP 路由、Agent 工具、轮询和 FFmpeg 携带明确 `user_id`；启动维护仅标记中断，不重提或恢复网络请求。
4. 项目、关联表、媒体、任务、用户设置、Prompt、Skill 和模型选择完成双用户隔离。
5. Qunl 真实 Session、禁用/删除后拒绝新访问实测通过，不新增同步删除资产要求。
6. 用户 A、B 经真实 Qunl 登录，分别在火宝页面完成 Agent 工具写入、图片生成、Mini 视频创建与轮询、媒体落盘和预览；公网接口直测不能替代该验收。
7. 本地并发、基本超时、上传和存储上限在实际入口生效，错误配置不回退其他 Key。
8. 旧数据和旧 Key 按显式用户 ID 完成可恢复迁移，未泄露 Key。
9. 自动化测试全部通过；不适用的历史结构断言按新边界更新并说明原因，不得放宽断言绕过失败；删除测试文件仍须先征得用户同意。
10. 浏览器桌面和移动视口完成 Qunl 入口、项目、设置、Agent、图片和视频工作流验收。
11. 文本流式、图片参考图、文生视频、视频下载和本地合并完成本阶段端到端验收；视频参考图放到下一阶段，不作为本阶段完成前提，也不标记为已验证或开放未验证入口。

任何一项未完成，都只能描述为“某一阶段完成”或“基础隔离可运行”，不能描述为“SaaS 化隔离完成”。
